Introduction to HTML

What are Markup Languages?

A markup language is a system for defining the structure, presentation, and/or purpose of content within a digital document so computer programs can interpret and display the content correctly. Markup languages encode text using specific vocabulary, symbols, and/or syntax rules. For example, the <h1> tag in HTML communicates that the enclosed text is a top-level heading. Search engines can use this information to better understand the subject matter of your page, while browsers can use this information to apply the relevant styling.

Markup languages can:

  • Make your website more search engine-friendly
  • Ensure your content displays consistently across different technologies
  • Improve website accessibility

Frontend Development

Front-end development is designing and creating the front end, or design side, of a website, application, or other development project. When you think of a website you like to visit, you might picture the colors, logo, and other design elements you see when navigating the home page. You can click links that take you to other pages on the website, each containing text, images, links to navigate to different pages, buttons to click, menus that expand when you hover your pointer over them, and more. All of these elements allow you, the user, to find the information you're looking for in an intuitive and pleasant way. While a back-end developer is the professional who writes the base code that allows the website to function, a front-end developer designs these elements so that users can have a positive experience while engaging with the website.

HTML

HTML is the most basic building block of the Web. It defines the meaning and structure of web content. Other technologies besides HTML are generally used to describe a web page's appearance/presentation (CSS) or functionality/behavior (JavaScript). "Hypertext" refers to links that connect web pages to one another, either within a single website or between websites. Links are a fundamental aspect of the Web — by uploading content and linking it to pages created by other people, you become an active participant in the World Wide Web.

CSS

CSS is a language that describes the style of an HTML document — how elements should be displayed. It can control the layout of multiple pages all at once, saving a lot of repeated work.

JavaScript (JS)

JavaScript is a lightweight interpreted (or just-in-time compiled) programming language with first-class functions. While it's most well-known as the scripting language for web pages, many non-browser environments use it too, such as Node.js, Apache CouchDB, and Adobe Acrobat. It's a prototype-based, garbage-collected, dynamic language supporting multiple paradigms — imperative, functional, and object-oriented.

What is HTTP?

HTTP is the foundation of the World Wide Web, and is used to load webpages using hypertext links. HTTP is an application layer protocol designed to transfer information between networked devices and runs on top of other layers of the network protocol stack. A typical flow over HTTP involves a client machine making a request to a server, which then sends a response message.

Domain Name

Domain names are human-friendly web addresses (e.g., google.com) substituting numerical IP addresses. Comprise second-level (google) and top-level (.com) domains. Registered through registrars, essential for branding and online presence. DNS translates names to IP addresses for accessibility.

Hosting

Web hosting stores website files on servers, making sites accessible online. Types include shared (multiple sites per server) and dedicated (exclusive server) hosting. Providers offer additional services like email, domains, and security certificates. Critical for website performance and accessibility.

DNS

DNS translates human-readable domain names into IP addresses through a global, decentralized server network. Enables easy internet navigation by converting names like www.example.com to numeric addresses browsers can connect to.

Browsers

Web browsers request and display websites by interpreting HTML, CSS, and JavaScript. Use rendering engines (Blink, Gecko) for display and JavaScript engines (V8) for code execution. Handle security, bookmarks, history, and user interactions for web navigation.

Search Engine Optimization (SEO)

SEO is the practice of improving your website to increase its visibility when people search for products or services related to your business in search engines like Google. The better visibility your pages have in search results, the more likely you are to garner attention and attract prospective and existing customers to your business. A related concept, GEO, focuses on optimizing content for AI-powered search experiences, ensuring your information is accurately and effectively presented in AI-generated summaries and responses.

Your First HTML File

Creating your first HTML file is simple. Follow these steps:

  1. Choose a text editor. Any basic editor (e.g., VS Code, Sublime Text, Notepad++) will work.
  2. Write the skeleton. Use the standard HTML5 boilerplate: 
                    <!DOCTYPE html>
                          <html lang="en">
                            <head>
                              <meta charset="UTF-8">
                              <meta name="viewport" content="width=device-width, initial-scale=1.0">
                              <title>My First Page</title>
                            </head>
                            <body>
                              <h1>Hello, World!</h1>
                            </body>
                          </html>
  3. Save the file as index.html (the .html extension is required). Open it in a browser by double-clicking the file or dragging it into any browser window. You should see the heading "Hello, World!"

This section teaches how to create a minimal HTML file, save it with the .html extension, and view it in a browser.

DOCTYPE Declaration

The <!DOCTYPE html> declaration represents the document type and helps browsers render the page correctly. It must be the very first line in your HTML file, before the <html> tag. In HTML5, the declaration is simple and case-insensitive.

Resource: MDN: Doctype

<html> Element

The <html> element is the root of an HTML page. All other elements must be descendants of this element. The lang attribute should be set on this element to declare the page's language, which is essential for screen readers and search engines.

Resource: MDN: <html> element

<head> Element

The <head> element contains machine-readable information about the document, such as <meta> tags, the <title>, links to stylesheets, and scripts. Content inside <head> is not directly displayed in the browser window.

Resource: MDN: <head> element

<body> Element

The <body> element contains the visible page content — text, images, videos, forms, and other HTML elements. There should be only one <body> per document, and it is a direct child of <html>.

Resource: MDN: <body> element

Meta Charset

The <meta charset="UTF-8"> tag sets the character encoding for the HTML document. UTF-8 supports all characters from all human languages and is the preferred encoding for modern web development.

Resource: MDN: <meta> charset attribute

Viewport Meta Tag

The <meta name="viewport" content="width=device-width, initial-scale=1.0"> tag ensures your page is properly scaled on mobile devices. This is essential for responsive design and mobile-first development.

Resource: MDN: Using the viewport meta tag

<title> Element

The <title> element defines the title of the document, shown in the browser's title bar or tab. A good title is descriptive, concise (50–60 characters), and includes relevant keywords for SEO.

Resource: MDN: <title> element

Semantic Document Structure

Proper use of semantic elements (<header>, <nav>, <main>, <section>, <article>, <aside>, <footer>) helps search engines and assistive technologies understand your page structure. Semantic HTML also improves accessibility and SEO.

Resource: MDN: Semantics

Sample Code

Every concept from this section, assembled into one valid document: 

            <!DOCTYPE html>
                      <html lang="en">
                        <head>
                          <meta charset="UTF-8">
                          <meta name="viewport" content="width=device-width, initial-scale=1.0">
                          <title>HTML Document Structure | CodePath</title>
                        </head>
                        <body>
                          <header>
                            <h1>Understanding Document Structure</h1>
                          </header>
                          <main>
                            <section>
                              <h2>Why Structure Matters</h2>
                              <p>Every element above plays a distinct role in how this page is parsed and rendered.</p>
                            </section>
                          </main>
                          <footer>
                            <p>&copy; 2026 CodePath</p>
                          </footer>
                        </body>
                      </html>

Headings (<h1>–<h6>)

HTML headings define six levels of section headings. <h1> is the most important and typically used for the main title, while <h2>–<h6> denote subsections. Use headings hierarchically and skip levels sparingly. Only one <h1> per page is recommended.

Resource: MDN: HTML headings

Paragraphs (<p>)

The <p> element defines a paragraph of text. Avoid using <p> for line breaks — use CSS margins, or the <br> element sparingly for actual line breaks within poetry or addresses.

Resource: MDN: <p> element

Text Formatting

HTML provides several semantic elements for text formatting:

<strong>
Strong importance (preferred over <b> for semantic meaning)
<em>
Emphasized text (preferred over <i>)
<abbr>
Abbreviations and acronyms, with a title attribute
<blockquote>
Long quotations
<q>
Inline quotations
<code>
Inline code
<del>
Deleted text
<ins>
Inserted text
<mark>
Highlighted text

Resource: MDN: HTML elements reference

Line Breaks (<br>)

The <br> element produces a line break in text. Use it for poems, addresses, or other actual line-break situations — not for adding spacing between paragraphs (use CSS margin instead).

Resource: MDN: <br> element

Horizontal Rule (<hr>)

The <hr> element represents a thematic break between paragraph-level elements — ideal for separating sections of a document. It is a void element and does not require a closing tag.

Resource: MDN: <hr> element

Anchor Element (<a>)

The <a> element creates hyperlinks to other pages, files, or locations within the same page. The href attribute specifies the link destination. Always include descriptive link text (avoid "click here" or "read more" alone).

Resource: MDN: <a> element

Absolute vs Relative URLs

Absolute URLs include the full address (e.g., https://www.example.com/page) and work from any context. Relative URLs are relative to the current page's location (e.g., about.html, ../contact/index.html) and are better for internal linking and portability.

Resource: MDN: Creating links

Link Targets and Security

When opening links in a new tab, always include target="_blank" and rel="noopener noreferrer" to prevent the new page from accessing the original page via window.opener, improving security.

Resource: MDN: rel="noopener"

Named Anchors (Internal Linking)

Create intra-page links using the id attribute on any element and a corresponding fragment identifier in the href (e.g., <a href="#section-2">). This improves navigation for keyboard users and long documents.

Resource: MDN: Creating links

Accessible Link Text

Accessible link text should be descriptive enough to make sense out of context. Screen readers often list all links on a page, so "click here" is unhelpful, while "View our HTML course syllabus" is clear and useful.

Resource: WAI-ARIA Authoring Practices: Links

Sample Code

<nav>
    <a href="#section-2">Jump to Section 2</a>
    <a href="about.html">About This Course</a>
    <a href="https://developer.mozilla.org/" target="_blank" rel="noopener noreferrer">
        Open the MDN documentation
    </a>
</nav>

<h2 id="section-2">Section 2</h2>
<p>Clicking the first link above jumps straight here.</p>

Images (<img>)

The <img> element embeds images into a page. The src attribute specifies the image source, and the required alt attribute provides alternative text for screen readers and when images fail to load. Descriptive alt text is essential for accessibility.

Resource: MDN: <img> element

Figure and Caption (<figure>, <figcaption>)

Use the <figure> element to group an image, diagram, code snippet, or other media with its caption, wrapped in <figcaption>. This associates the media with its description semantically.

Resource: MDN: <figure> element

SVG Graphics

Scalable Vector Graphics (SVG) can be embedded directly using <svg> elements or as image sources. SVG graphics are resolution-independent and ideal for icons, logos, and illustrations.

Resource: MDN: Including vector graphics in HTML

Video and Audio

The <video> and <audio> elements embed media files. Always include controls for user interaction, and provide a poster image for video. For accessibility, add <track> elements for captions and subtitles.

Resource: MDN: HTML video and audio

Sample Code

<figure>
    <img src="team-photo.jpg" alt="The CodePath team at the 2026 launch event" width="600">
    <figcaption>Our team at the 2026 launch event</figcaption>
</figure>

<svg viewBox="0 0 24 24" width="24" height="24" role="img" aria-label="Checkmark icon">
    <path d="M9 16.2 4.8 12l-1.4 1.4L9 19 21 7l-1.4-1.4z"></path>
</svg>

<video controls poster="lesson-preview.jpg" width="480">
    <source src="lesson.mp4" type="video/mp4">
    <track kind="captions" src="lesson-captions.vtt" srclang="en" label="English">
    Your browser doesn't support embedded video.
</video>

Table Element (<table>)

The <table> element displays tabular data. Use tables for data that naturally fits in rows and columns — not for page layout. <thead>, <tbody>, and <tfoot> can be used to structure the table.

Resource: MDN: <table> element

Table Rows and Cells (<tr>, <td>, <th>)

<tr> defines a table row, <td> defines a standard cell, and <th> defines a header cell. Header cells are typically bold and centered by default, and should be used for row or column headers.

Resource: MDN: <td> element

Table Headers (<th> scope attribute)

The scope attribute on <th> elements defines whether a header applies to a row, column, or group of rows/columns. Values include row, col, rowgroup, and colgroup. This is crucial for screen reader navigation of tables.

Resource: MDN: <th> scope attribute

Accessible Tables

For complex tables, use <caption> for a summary, <thead> for header rows, and id/headers attributes to associate data cells with their headers. Never use <table> for page layout — it harms accessibility and SEO.

Resource: MDN: HTML table accessibility

Sample Code

<table>
    <caption>Course Progress by Track</caption>
    <thead>
        <tr>
            <th scope="col">Track</th>
            <th scope="col">Modules Complete</th>
            <th scope="col">Status</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <th scope="row">HTML</th>
            <td>1</td>
            <td>In progress</td>
        </tr>
        <tr>
            <th scope="row">Python</th>
            <td>3</td>
            <td>In progress</td>
        </tr>
        <tr>
            <th scope="row">Linux</th>
            <td>1</td>
            <td>Paused</td>
        </tr>
    </tbody>
</table>

Summary

Form Element (<form>)

The <form> element collects user input and sends it to a server. The action attribute specifies the URL to send data to, and method defines the HTTP method (usually GET or POST).

Resource: MDN: <form> element

Form Inputs (<input>)

The <input> element is the most versatile form element. The type attribute determines the input kind (text, email, password, number, checkbox, radio, file, etc.). Always include a corresponding <label>.

Resource: MDN: <input> element

Label Association

Associate text labels with form inputs using the for attribute on the <label> matching the id on the input, or by wrapping the input inside the <label>. This improves accessibility and toggles focus when clicking the label.

Resource: MDN: <label> element

Form Controls: Textarea, Select, Button

<textarea> for multi-line text, <select> for dropdown lists, and <button> for submit/reset actions. Each should have a descriptive label for accessibility.

Resources: MDN: <textarea> | MDN: <select> | MDN: <button>

Form Validation

Use HTML5 input types and attributes (required, min, max, pattern) for built-in client-side validation. Always provide server-side validation as well, since client-side validation can be bypassed.

Resource: MDN: Client-side form validation

Sample Code

<form action="/signup" method="post">
    <label for="email">Email</label>
    <input type="email" id="email" name="email" required>

    <label for="age">Age</label>
    <input type="number" id="age" name="age" min="13" max="120">

    <label for="track">Track</label>
    <select id="track" name="track">
        <option value="html">HTML</option>
        <option value="python">Python</option>
    </select>

    <label>
        Goals
        <textarea name="goals" rows="3"></textarea>
    </label>

    <button type="submit">Sign Up</button>
</form>

Summary

Element / Attribute Example Purpose

<input> type="email" Versatile single-value input
<label> for="email" Ties descriptive text to a control
<textarea> — Multi-line text input
<select> — Dropdown of options

Semantic Document Landmarks

HTML5 introduced semantic elements that describe the purpose of content:

<header>
Introductory content or navigational links
<nav>
Navigation links
<main>
Primary content of the document
<section>
Thematic grouping of content
<article>
Independent, self-contained content
<aside>
Content tangentially related (sidebars, callouts)
<footer>
Footer information, copyright, related links

Resource: MDN: HTML elements reference — Content sectioning

When NOT to Use Semantic Elements

Avoid using semantic elements solely for styling purposes. Use <div> or <span> when no semantic meaning is appropriate, and style with CSS. Overusing or misnesting semantic elements can confuse assistive technologies, since screen readers navigate primarily by heading rank (<h1>–<h6>), not by how sectioning elements are nested.

Resource: MDN: Heading elements

Sample Code

<body>
    <header>
        <h1>CodePath</h1>
        <nav>...</nav>
    </header>

    <main>
        <article>
            <h2>Why Semantics Matter</h2>
            <section>
                <h3>For Screen Readers</h3>
                <p>...</p>
            </section>
        </article>

        <aside>
            <h2>Related Tracks</h2>
        </aside>
    </main>

    <footer>
        <p>&copy; 2026 CodePath</p>
    </footer>
</body>

Summary

Semantic Landmarks at a Glance
Element Implicit ARIA Role Use When
<header> banner Site or section intro
<nav> navigation A block of navigation links
<main> main The page's unique content (once per page)
<section> (context-dependent) A themed group, usually with its own heading
<article> article Content that could stand alone (post, comment)
<aside> complementary Tangential content (sidebar, pull quote)
<footer> contentinfo Closing info for a page or section
